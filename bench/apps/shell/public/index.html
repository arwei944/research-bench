◈ 外壳

平台层。负责路由分发、应用注册表、主题与模式注入。它坏了，所有应用都打不开。 这一层刻意保持极薄——只有 3 个文件，逻辑不超过 400 行。

1
请求进来
server.mjs 按路径前缀分发：/ 外壳、/app/<id>/ 应用前端、/api/<id>/ 应用后端、/api/_platform/* 平台 API。
2
扫描应用
lib/registry.mjs 每次请求都重新读 apps/ 目录，所以新增/删除目录即刻生效。同时解析 app.json 的 layer 字段并检查依赖合法性。
3
加载应用后端
server.mjs 按 mtime 缓存动态 import 应用的 server.mjs，改了代码下次请求自动重载。routes 做精确匹配，dynamicRoutes 做正则匹配。
4
注入主题与模式
把 data-theme / data-mode 写进 iframe 的 <html>，并通过 postMessage 下发 CSS 变量与 appMode。

分层规则

见 bench/lib/layers.mjs。核心规则：

L0 platform  不依赖任何层
L1 core      只能依赖 L0
L2 app       只能依赖 L0 / L1
L3 lab       可以依赖任何层（实验品允许乱来）

反向影响：下层坏了 → 依赖它的上层全废
         上层坏了 → 下层不受影响
