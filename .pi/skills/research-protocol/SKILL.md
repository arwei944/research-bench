# Research Protocol · 通用研究协议

> 触发时机:当用户提出任何需要"调研/研究/分析/了解某主题"的任务时,遵循本协议。这是所有研究任务的默认工作方式。

## 0. 为什么必须有协议

研究智能体的最大风险是**幻觉与虚构引用**。已核验数据:GPT-3.5 虚构引用率 55%,即使 GPT-4 仍达 18%(Walters & Wilder, *Scientific Reports* 2023)。因此本协议把"证据可追溯"作为强制要求,而非可选项。

## 1. 强制流水线(五阶段)

### 阶段一:问题拆解
- 把用户问题改写为 1 个主问题 + 3~5 个研究子问题。
- 明确:范围边界(时间/地域/领域)、产出物类型(概述/综述/报告/教学)、读者视角。
- 输出一句研究计划,请用户确认或直接继续(若明确)。

### 阶段二:多源检索
- 至少 2~3 个独立来源,优先一手/权威来源。
- 学术问题:arXiv / PubMed / Crossref / 学校数据库。
- 金融问题:官方披露(财报/公告/监管)、行情数据、权威媒体。
- 一般问题:官方文档、维基百科、权威媒体,交叉来源。
- 记录每一条来源的:**标题、发布者、日期、URL**(若可获取)。

### 阶段三:证据筛选与分级
| 级别 | 定义 | 使用方式 |
|---|---|---|
| A | 一手数据:论文、财报、官方公告、原始数据 | 可直接支撑结论 |
| B | 权威二手:顶级期刊综述、央行/监管报告、头部媒体核验报道 | 可支撑,标注转引 |
| C | 一般二手:博客、普通媒体、社交内容、AI 生成内容 | 仅作线索,不直接作为结论依据 |
- 每项关键论断标注证据级别。

### 阶段四:交叉验证与引用核验
- 关键数字/事实尽量找第二个独立来源确认;不一致时**并列呈现分歧**,不强行统一。
- **引用核验**:凡给出论文/文献引用,使用 Crossref/PubMed/arXiv 校验其真实存在(真实作者、标题、年份、DOI)。输出逐条状态:✅已核验 / ⚠️未找到 / ❌疑似虚构。禁止输出未核验的"看起来合理"的引用。
- 数据日期必须标注(金融/新闻尤其重要)。

### 阶段五:结构化成稿与沉淀
- 按《报告模板》输出。
- 产出保存到 `knowledge-base/` 对应领域目录,命名 `YYYY-MM-DD-主题.md`,头部记研究日期与使用模型/数据源。

## 2. 报告模板

```markdown
# 研究主题
> 研究日期:YYYY-MM-DD ｜ 模型/数据源:(实际使用) ｜ 置信度:高/中/低

## 结论速览
- **核心结论 1** (证据A级,置信度高)
- **核心结论 2** (证据B级,存在分歧,见§3)

## 背景与问题拆解
(研究子问题清单)

## 分节论述
(每个子问题一节,含证据、来源标注、反方观点)

## 分歧与不确定点
| 议题 | 观点A(来源) | 观点B(来源) | 我们的判断 |
|---|---|---|---|
| ... | ... | ... | ... |

## 引用清单(均经核验)
1. 作者, 标题, 年份, DOI/URL [✅已核验]
...

## 参考与扩展阅读
```

## 3. 知识库沉淀规范
- 目录:`knowledge-base/{academic|finance|learning}/YYYY-MM-DD-主题.md`
- 每个主题文件头部用 YAML frontmatter:
  ```yaml
  ---
  title: 主题
  date: YYYY-MM-DD
  domain: academic|finance|learning
  confidence: high|medium|low
  sources: [来源1, 来源2]
  status: active|reference
  ---
  ```

## 4. 质量门禁清单(成稿前逐项自检)
- [ ] 每个关键论断都有来源标注?
- [ ] 所有文献引用已通过 Crossref/PubMed/arXiv 核验,无"疑似虚构"?
- [ ] 数据/新闻标注了日期与来源?
- [ ] 分歧点是否并列呈现而非掩盖?
- [ ] 是否明确标注了置信度与已知反方观点?
- [ ] 产出已按规范保存到 knowledge-base?
